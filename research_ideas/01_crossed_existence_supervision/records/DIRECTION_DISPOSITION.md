# Direction 01 disposition (screening stage)

**Disposition: insufficient evidence for the tested exact-query cross-video pairwise-loss fallback.** This is not a test or rejection of the intended complete crossed-quartet supervision method.

The pilot tested whether adding a small exact-query positive/negative cross-video margin loss to the same 50,049-parameter pooled readout would improve strict-inner Novel-dev existence discrimination. It used seed 3407 and two independently held-out semantic folds, A1 action 01 and C1 composition 01, with 5 planned epochs and earliest-tie Seen-val AUROC checkpoint selection. The official U test split was not opened. This is exploratory development evidence, not a frozen final evaluation.

The action fold changed pooled Novel AUROC from 0.6277 to 0.6157 (-1.20 pp; video-cluster paired bootstrap 95% interval [-2.83,+0.38] pp) and same-query cross-video PairAcc from 0.449 to 0.427 (-0.022). The composition fold changed pooled Novel AUROC from 0.5536 to 0.5546 (+0.11 pp; interval [-0.28,+0.48] pp) and PairAcc from 0.507 to 0.516 (+0.009). Seen AUROC changed +0.16 pp and -0.05 pp, respectively. Both folds' same-video PairAcc point estimates were retained; the saved predictions lacked source-pair identities needed for a valid cluster interval, so no interval is claimed.

Query-only Novel AUROC exceeded the trained pooled readout on both folds (0.671 vs 0.628; 0.583 vs 0.554), while video-only AUROC was near 0.5 (0.500 and 0.494). Re-forwarding after a deterministic whole-video derangement reduced retained-label pooled AUROC by about 1.5–2.0 pp. These are signs of both language predictive signal and some video dependence; the shuffle retains original labels and is only a dependence diagnostic. It does not establish correct compatibility. The query-only same-query PairAcc estimate is unexpectedly above 0.5 in C1; investigate feature/row semantics before interpreting it as a query prior result.

The action result opposes the tested fallback; the composition result is effectively null. This is not an implementation failure in the completed runs. No complete reliable 2x2 crossed-matrix eligibility count has yet been certified, and pair fallback evidence cannot answer the intended crossed-supervision hypothesis. Keep the result, do not scale this configuration, and continue to priority 02. Revisit 01 only if a strict audit identifies enough independent, reviewed, complete crossed matrices; then test the prescribed crossed objective directly with a new frozen config.

Engineering history: first action evaluation wrote predictions and metrics, then exited nonzero because a status print passed an unsupported `flush` argument to JSON serialization; the scheduler's artifact validation reused the valid checkpoint and outputs and completed the task on retry. The initial action shuffle task hit an isolated `NameError` in unused loader code and exhausted two retries; a code fix was recorded and new `repair1` task/config IDs completed successfully. Failed task records and outputs remain intact. The summarizer was also corrected to read both JSON and JSONL result files. No repair changed effective batch size, budget, method, labels, or checkpoint selection.
